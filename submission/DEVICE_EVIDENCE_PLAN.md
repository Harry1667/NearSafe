# 安心圈實機證據計畫

> 隊名：山形。目的不是把「程式已寫」說成「功能已驗證」，而是讓每一項競賽主張都有可重現的實機畫面、時間戳與診斷紀錄。

## 測試裝置

- 建議：兩台實體 iPhone、兩個不同 iCloud 帳號，系統版本與機型記入紀錄。
- 第一輪：Xcode Debug 直裝，使用實機診斷金手指找錯。
- 第二輪：介面封版後 TestFlight 安裝，驗證 production APNs 與正式使用流程。
- 不把模擬器的本機通知、假位置或示範資料當成實機背景能力證據。

## 共同準備

1. 兩台 iPhone 都開啟 Wi-Fi／行動網路並登入不同 iCloud 帳號。
2. A 建立家庭分享，B 接受邀請；錄下 A 邀請、B 接受、雙方看到同一家庭的完整流程。
3. 兩台皆開啟 App → 設定 → Debug 實機測試 → 實機診斷金手指，清除舊 Log 後執行一鍵檢查。
4. A 要分享即時圈時，把定位設為「永遠」；通知設為允許。B 只在需要自行分享位置時要求「永遠」。
5. 報告、影片與截圖不得露出完整 token、Apple ID、精確住址、精確座標或家人真名。

## E01：可見 APNs 閉環

1. A 將 App 放到背景並鎖屏。
2. 使用 Apple Push Notification Console 或 HavenCircle 伺服器，對 A 的正確環境送出可見通知。
3. 同一段錄影中拍到鎖屏收件、點擊通知、App 開啟提醒中心。
4. 保存 Apple delivery log 或伺服器 `sent=1` 回應，遮蔽 token。

通過條件：遠端送出紀錄成功、鎖屏收到、點擊 deep link 正確；三項缺一不可。

## E02：無聲 APNs 背景喚醒

1. 清除 A 的診斷 Log，開啟 App 後回主畫面並鎖屏。
2. 送出無聲 APNs，等待 iOS 調度；記錄送出時間。
3. 再開 App，複製診斷報告。
4. 確認有「收到背景遠端通知」與事件管線完成；若沒有新的相關事件，沒有橫幅屬正確行為。

通過條件：遠端送出成功，裝置 Log 有 callback 與完成結果。不能用 5 秒本機通知代替。

## E03：背景／鎖屏即時圈

1. A 開啟自己的即時圈；B 停在家人頁或地圖，錄下 A 的初始「最新位置」與更新時間。
2. A 回主畫面並鎖屏，**不要從 App Switcher 強制結束**。
3. 攜帶 A 移動約 300–500 公尺，等候 5–15 分鐘；背景頻率由 iOS 決定，不預設固定秒數。
4. B 重新整理或重新進入畫面，錄下最新位置與更新時間變化。
5. 重開 A，匯出診斷報告。確認 Log 有 App 進入背景、背景定位回呼與 CloudKit 上傳成功；報告只留精度與時間，不留座標。
6. A 停止分享，確認 B 移除即時圈或顯示停止狀態。

通過條件：A 鎖屏後位置確有變化、B 看到更新、A 的 Log 有背景定位與 CloudKit 成功、停止分享可傳到 B。

## E04：過期保護

1. 先讓 A 成功分享一筆位置，記錄 B 的時間。
2. 關閉 A 的定位權限或網路，保留超過 15 分鐘，不偽造系統時間。
3. B 重新整理，錄下「位置已過期」文字與警報排除狀態。
4. 恢復權限／網路，確認狀態可恢復更新。

通過條件：舊位置不冒充現在位置，而且狀態有文字標籤，不只靠顏色。

## E05：家庭安否閉環

1. A 在真實或明確標示的演練事件中請家人回報。
2. B 回報「我平安」。
3. A 看到 B 的回報並標記已讀。
4. B 看到已讀回條。

通過條件：跨兩個 iCloud 帳號完成「請求 → 回報 → 已讀 → 回條」，全程一鏡錄下。

## 邊界測試

以下結果不預設成功，照實記錄即可：

- A 從 App Switcher 強制結束後，系統是否仍重新啟動定位服務。
- 低耗電模式下更新是否延遲。
- 斷網後恢復是否補上最新一筆，而非形成位置軌跡。
- 定位改成「使用 App 期間」後，UI 是否明確警告背景能力受限。
- 拒絕通知後，App 是否仍能顯示 App 內提醒並提供前往設定入口。

## 對外敘事規則

- 有 E01–E05 證據才把對應列從「已實作、驗證中」改為「已驗證」。
- 背景更新只陳述實測範圍，不宣稱保證 30 秒或任何固定頻率。
- 即時圈是本人主動開啟的最新位置分享，只保留最新一筆，不建立位置軌跡。
- 安心圈不是緊急服務；緊急狀況仍直接撥打 110／119。
